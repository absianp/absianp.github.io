“업무를 자동화해 드립니다”라는 설명만으로는 의뢰인이 무엇을 받는지 알기 어렵습니다. 첫 작업은 “신청 내용을 한 곳에 모으고, 담당자가 확인할 수 있게 알립니다” 정도로 좁혀 보세요. 구현할 기능과 납품 후 책임을 정하기가 쉬워집니다.

아래는 **신청 접수 자동화를 맡는 상황을 가정한 설계 예시**입니다. 특정 고객의 납품 사례나 수익 실적을 소개하는 글은 아닙니다.

## 먼저 입력과 결과를 한 문장으로 정합니다

의뢰인이 이미 쓰는 폼과 시트를 유지할 수 있는지부터 확인합니다. 새 서비스를 늘리면 구독료뿐 아니라 계정 관리와 인수인계도 늘어납니다. Google Forms를 사용하는 경우 응답을 Google Sheets에 연결하는 기능부터 검토할 수 있습니다. 별도 자동화 도구 없이 가능한 범위를 먼저 살펴보세요. [Google Forms 응답 관리 안내](https://support.google.com/docs/answer/139706?hl=ko)

이번 예시의 작업 문장은 다음과 같습니다.

> 신청 폼의 응답을 접수 시트에 기록하고, 새 접수가 있다는 사실과 접수 번호를 지정한 담당자 채널에 알린다. 담당자가 접수 상태를 바꾸는 일은 수동으로 남긴다.

전화 상담, 결제, 자동 환불, 고객에게 보내는 문자는 이 문장에 들어 있지 않습니다. 추가로 요청받으면 기능과 비용을 별도로 정합니다.

## 접수 시트는 오류를 찾을 수 있게 만듭니다

| 열 이름 | 들어갈 내용 | 필요한 이유 |
|---|---|---|
| 접수 ID | 폼 응답 ID 등 재실행해도 같은 값 | 같은 신청을 두 번 처리하지 않기 위해 |
| 접수 시각 | 원본 응답 시각과 시간대 | 늦게 처리된 신청을 구분하기 위해 |
| 신청 항목 | 상담·견적 등 선택값 | 담당자가 내용을 분류하기 위해 |
| 연락처 | 업무에 필요한 최소 항목 | 신청자에게 연락하기 위해 |
| 처리 상태 | 접수·확인·완료 | 사람이 처리한 결과를 기록하기 위해 |
| 알림 상태 | 대기·성공·실패 | 접수 저장과 알림 발송 결과를 구분하기 위해 |
| 마지막 오류 | 오류 종류와 확인 시각 | 실패한 부분만 다시 처리하기 위해 |

이메일 주소만으로 중복을 판단하면 같은 사람이 다른 날짜에 넣은 정상 신청까지 지울 수 있습니다. 플랫폼이 제공하는 응답 ID를 우선 쓰고, 그런 값이 없다면 어떤 항목의 조합을 한 건으로 볼지 의뢰인과 정합니다.

처리 순서도 문서로 남깁니다.

```text
응답 수신
→ 같은 접수 ID가 이미 있는지 확인
→ 새 접수이면 시트에 저장
→ 알림 전송
→ 해당 행의 알림 상태 갱신
```

시트 저장은 됐지만 알림만 실패했다면 새 행을 또 만드는 대신 기존 행의 알림을 다시 시도해야 합니다. 다만 알림 서비스가 메시지를 받은 뒤 응답만 끊긴 경우에는 중복 발송 가능성이 남습니다. 노코드 도구의 실행 기록에서 전송 결과를 확인할 방법까지 납품 범위에 넣으세요.

## 견적에는 실행 횟수와 운영 담당자를 적습니다

월 신청 수만 세면 비용을 과소평가하기 쉽습니다. 한 신청에서 조회, 행 생성, 메시지 전송, 상태 갱신이 각각 실행될 수 있고 재시도도 추가됩니다. 선택한 서비스가 어떤 동작을 과금하는지 확인한 뒤 다음 표를 채웁니다.

| 합의 항목 | 문서에 적을 내용 |
|---|---|
| 계정 소유자 | 폼·시트·자동화 계정은 누구 명의인지 |
| 구독료 | 고객 직접 결제인지, 견적에 포함하는지 |
| 예상 사용량 | 월 신청 수와 신청 한 건당 동작 수 |
| 수정 범위 | 기존 항목명 수정과 신규 기능 추가의 구분 |
| 장애 대응 | 확인 시간, 연락 방법, 서비스 자체 장애의 처리 |
| 종료 시 전달물 | 설정 설명, 실행 기록 위치, 접근 권한 회수 순서 |

초기 제작비와 매달 운영비를 나누어 적으면 “한 번 결제했으니 계속 관리해 주는 것 아니냐”는 오해를 줄일 수 있습니다. 금액은 작업 복잡도와 대응 범위를 보고 산정해야 하며 이 글에서 보편적인 수입을 제시할 수는 없습니다.

## 납품 확인은 정상 신청 한 건으로 끝내지 않습니다

실제 개인정보 대신 연습용 이름과 연락처를 써서 아래를 확인합니다.

1. 정상 신청: 시트 한 행과 알림 한 건이 서로 같은 접수 ID를 가리키는지 확인합니다.
2. 같은 응답 재처리: 같은 행이 추가되지 않는지 확인합니다.
3. 필수 항목 누락: 오류로 표시되고 정상 접수처럼 처리되지 않는지 확인합니다.
4. 알림 연결 해제: 접수 기록이 남고 알림 실패를 찾을 수 있는지 확인합니다.
5. 담당자 인수인계: 제작자가 없어도 실행 기록과 오류를 찾을 수 있는지 확인합니다.

납품 문서에는 각 경우의 입력, 확인 결과, 남은 제약을 짧게 적습니다. 이 기록이 있어야 운영 중 문제가 생겼을 때 처음부터 전체 설정을 뒤질 필요가 없습니다.
