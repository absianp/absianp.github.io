노션 템플릿을 판매할 때 구매자가 받아야 하는 것은 소개 이미지보다 **복제해서 쓸 수 있는 사본과 사용 설명**입니다. 결제 뒤 링크가 막혀 있거나 제작자의 원본을 수정하게 된다면 상품 설명이 좋아도 전달에 실패한 것입니다.

여기서는 간단한 주간 업무 템플릿을 준비한다고 가정합니다. 실제 판매 실적을 다루는 글은 아니며, 등록 전에 확인할 전달 구조를 설명합니다.

## 판매용 사본에서 실제 업무 정보를 먼저 지웁니다

개인용 페이지를 그대로 공개하지 말고 판매용 사본을 따로 만듭니다. 예제 행에는 가상의 업무만 남깁니다. 연결된 데이터베이스, 하위 페이지, 첨부 파일, 댓글에도 개인 정보가 남아 있지 않은지 확인합니다.

예를 들어 다음 정도의 간단한 구조부터 시작할 수 있습니다.

| 속성 | 형식 | 예제 값 |
|---|---|---|
| 업무 | 제목 | 다음 주 일정 정리 |
| 상태 | 선택 | 예정·진행·완료 |
| 기한 | 날짜 | 구매자가 직접 지정 |
| 메모 | 텍스트 | 필요한 자료 위치 기록 |

오늘 할 일 보기와 전체 목록 보기처럼 실제로 쓸 화면을 정리하고, 비어 있는 처음 상태에서도 사용자가 무엇을 입력해야 하는지 설명합니다. 자동 알림이나 외부 서비스 연동을 포함하지 않았다면 상품 설명에도 그렇게 적습니다.

## 게시와 복제를 각각 확인합니다

노션에서는 페이지를 웹에 게시하는 설정과 템플릿 복제를 허용하는 설정을 확인해야 합니다. 게시된 페이지의 하위 페이지와 공유 범위를 함께 점검하세요. 공개 링크를 가진 사람이 볼 수 있으므로 판매 링크 자체가 강한 접근 통제 수단은 아닙니다. [Notion 웹 게시 안내](https://www.notion.com/help/public-pages-and-web-publishing)

설정 후에는 제작자 계정에서만 열어 보지 않습니다. 로그아웃한 브라우저에서는 페이지가 보이는지, 별도 테스트 계정에서는 사본을 만들 수 있는지 확인합니다. 복제 뒤 원본이 바뀌지 않는지도 봅니다.

특히 외부 데이터베이스를 보여 주는 연결된 보기라면, 겉모습은 복제되어도 원본 접근 권한을 요구할 수 있습니다. 판매용 페이지 안에 필요한 데이터가 모두 포함되도록 구성하고 테스트 계정에서 각 보기를 열어 봅니다.

## 구매자에게 전달할 안내를 한 파일로 만듭니다

Gumroad에서 전달할 자료에는 아래 내용을 담습니다. 링크를 안내하는 PDF나 텍스트 파일, 상품의 구매 후 콘텐츠 등 사용할 전달 방식에 맞춰 준비합니다.

```text
주간 업무 템플릿 v1.0

포함 내용
- 업무 목록과 상태·기한 속성
- 전체 목록과 오늘 할 일 보기
- 가상 예제 업무

시작 방법
1. 노션 계정에 로그인합니다.
2. 아래 템플릿 링크를 엽니다.
3. 복제 기능으로 본인 워크스페이스에 사본을 만듭니다.
4. 예제 업무를 지우고 본인의 업무를 입력합니다.

템플릿 링크: [본인이 확인한 공개 복제 링크]
문의 방법: [실제로 확인하는 연락 경로]
지원 범위: 복제 오류와 기본 사용법 안내
포함되지 않는 작업: 개인 업무 맞춤 제작, 외부 서비스 연동
```

대괄호 부분을 채우기 전에는 판매용 파일로 올리지 않습니다. 지원 기간, 업데이트 제공 범위, 이용 가능한 계정 수와 재판매 조건도 본인이 제공할 수 있는 범위로 정합니다.

## 상품 설명은 받는 것과 받지 못하는 것을 분명히 씁니다

상품 등록 화면에서 디지털 상품의 제목, 설명, 가격, 미리보기, 전달 자료를 구성합니다. 화면과 제공 옵션은 바뀔 수 있으므로 현재 등록 화면과 [Gumroad 도움말](https://gumroad.com/help)을 함께 확인하세요.

“생산성 5배” 같은 측정하지 않은 효과 대신 “상태와 기한으로 업무를 분류하는 노션 템플릿”처럼 기능을 씁니다. 미리보기에도 실제 템플릿 화면을 사용하고, 예제 데이터임을 표시합니다. 구매자가 알아야 하는 노션 계정 요건과 별도 유료 기능 여부도 적습니다.

가격을 정할 때는 표시 가격을 그대로 수입으로 보지 않습니다. 판매 경로 등에 따른 수수료와 정산 조건은 [Gumroad 요금 안내](https://gumroad.com/pricing)에서 확인하고, 지원에 드는 시간까지 생각해 결정합니다.

## 마지막에는 테스트 구매로 전달 흐름을 확인합니다

Gumroad는 자신의 상품을 확인하는 테스트 구매 방법을 안내합니다. 판매자 계정으로 로그인한 상태에서 테스트 결제 흐름을 사용하며, 본인의 실제 카드로 자기 상품을 구매하는 방식은 사용하지 않습니다. [Gumroad 테스트 구매 안내](https://gumroad.com/help/article/62-testing-a-purchase)

테스트에서는 결제 완료 화면, 안내 메일, 전달 파일 열기, 템플릿 링크 접근, 노션 복제까지 이어서 확인합니다. 파일 이름과 템플릿 버전이 맞는지도 봅니다. 결제가 끝났다는 사실만으로 구매자가 템플릿을 사용할 수 있다고 판단하지 않는 것이 좋습니다.
