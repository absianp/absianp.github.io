- question: 회의가 끝난 후 음성 파일(m4a, mp3)을 올리면 자동으로 노션에 등록되게 만들려면 어떻게 해야 하나요?

# ChatGPT API와 노션 연동으로 끝내는 주간 회의록 자동 요약 및 액션아이템 정리 가이드 (2025 최신)

매주 월요일 오전마다 진행되는 1시간 남짓의 주간 스프린트 회의, 끝나고 나면 녹음 스크립트를 뒤적거리며 핵심 결정 사항과 각 담당자별 액션 아이템(To-Do)을 정리하느라 1~2시간씩 소모하고 계시진 않나요? 개발과 비즈니스 로직에 집중해야 할 엔지니어와 기획자가 단순 회의록 포맷팅에 귀중한 리소스를 낭비하는 것은 조직 차원에서도 명백한 손실입니다.

최신 **OpenAI Structured Outputs** 기능과 **Notion API v1**을 파이썬 파이프라인으로 연결하면, 회의 전문 텍스트를 입력하는 즉시 **정제된 요약문, 결정 사항, 체크박스형 액션 아이템**이 노션 데이터베이스에 완벽한 스키마로 자동 기록됩니다. 이 글에서는 수작업 대비 작성 시간을 90% 이상 단축하고, API 토큰 비용을 최소화하면서 프로덕션 레벨의 안정성을 갖춘 자동화 워크플로우를 완벽하게 구축해 봅니다.

---

## 1. 왜 'API 기반 자동화 파이프라인'을 구축해야 하는가?

많은 팀이 노션 AI(Notion AI) 기본 내장 기능이나 웹 브라우저의 ChatGPT 인터페이스를 활용합니다. 하지만 실무 환경에서는 다음과 같은 병목에 직면합니다.

- **스키마 불일치**: 일반 프롬프트 명령은 모델 실행 시마다 출력 형식(Markdown 헤더, 리스트 기호, 불릿 등)이 달라져 노션의 특정 프로퍼티(Tags, Date, Checkbox)에 일관되게 매핑할 수 없습니다.
- **워크스페이스 확장 비용**: 노션 AI는 유저당 월 $8~10 수준의 정액 요금이 부과되어 팀 규모가 커질수록 비용 부담이 급증합니다. 반면 `gpt-4o-mini` API를 활용하면 1시간 분량의 회의록 1건을 처리하는 데 채 10원도 들지 않습니다.
- **시스템 확장성 한계**: 슬랙(Slack), 음성인식(STT) 파이프라인, CI/CD 배포 알림 등 외부 도구와의 트리거 연동이 불가능합니다.

OpenAI의 정형화된 JSON 파싱 기능과 노션 블록 API를 조합하면, 데이터 정합성을 100% 보장하는 무인 자동화 체계를 완성할 수 있습니다.

## 2. 사전 준비: Notion Integration 발급 및 DB 설계

자동화를 시작하기 전, 노션 워크스페이스에서 API 권한을 생성하고 회의록을 적재할 데이터베이스 속성을 정의해야 합니다.

### Step 1: Notion Internal Integration 토큰 발급
1. [Notion Developers 포털](https://www.notion.so/my-integrations)에 접속하여 **'+ 새 통합(New integration)'**을 클릭합니다.
2. 관련 워크스페이스를 지정하고 이름을 입력(예: `Meeting-Summarizer-Bot`)한 뒤 생성합니다.
3. 생성된 **내부 통합 시크릿(Internal Integration Secret)** 키(`secret_...`)를 복사해 안전한 곳에 보관합니다.

### Step 2: 노션 데이터베이스 생성 및 스키마 매핑
회의록을 저장할 새 데이터베이스를 생성하고, 아래의 속성(Properties)을 정확히 추가합니다.

- **회의명 (Name / Title)**: 회의 제목 (Title)
- **일자 (Date)**: 회의 진행 날짜 (Date)
- **카테고리 (Category)**: 다중 선택 (Multi-select) - 예: `개발`, `스프린트`, `기획`
- **작성자 (Author)**: 텍스트 (Rich Text) 또는 사람 (People)

> [!IMPORTANT]
> 데이터베이스 우측 상단의 `...` 아이콘 > **연결(Connect to)** 메뉴를 눌러 방금 생성한 `Meeting-Summarizer-Bot`을 반드시 추가해야 404 `object_not_found` 오류 없이 데이터베이스 조회가 가능합니다.

데이터베이스 URL(`https://www.notion.so/{workspace_name}/{database_id}?v={view_id}`)에서 32자리 영숫자로 이루어진 `{database_id}` 값을 추출해 둡니다.

## 3. OpenAI Structured Outputs를 이용한 무결점 요약 추출

OpenAI의 최신 파이썬 SDK에서는 Pydantic 클래스를 활용해 LLM의 응답을 강력한 타입 힌팅과 함께 정형화할 수 있습니다. 환각이나 포맷 누락 없이 안정적으로 데이터를 파싱하는 구조를 정의합니다.

### Pydantic 스키마 정의 (`schema.py`)

```python
from typing import List
from pydantic import BaseModel, Field

class ActionItem(BaseModel):
    task: str = Field(description="구체적인 실행 과제 내용")
    assignee: str = Field(description="담당자 이름 (언급이 없으면 '미지정')")
    priority: str = Field(description="우선순위: High, Medium, Low 중 하나")

class MeetingAnalysis(BaseModel):
    title: str = Field(description="회의의 핵심 주제를 요약한 명확한 제목")
    tags: List[str] = Field(description="회의와 관련된 키워드 태그 (최대 3개)")
    summary_points: List[str] = Field(description="핵심 논의 내용 3~5줄 불릿 요약")
    key_decisions: List[str] = Field(description="회의에서 최종 결정/합의된 사항")
    action_items: List[ActionItem] = Field(description="도출된 To-Do 과제 목록")
```

## 4. 파이썬 엔드투엔드(E2E) 자동화 스크립트 구현

이제 OpenAI API로 회의록 텍스트를 분석하고, 분석된 JSON 객체를 노션의 Page Properties 및 Child Blocks(`heading_2`, `bulleted_list_item`, `to_do`)로 변환해 적재하는 메인 파이프라인을 작성합니다.

### 패키지 설치

```bash
pip install openai notion-client pydantic python-dotenv
```

### 자동화 메인 코드 (`run_sync.py`)

```python
import os
from datetime import datetime
from dotenv import load_dotenv
from openai import OpenAI
from notion_client import Client
from schema import MeetingAnalysis

load_dotenv()

OPENAI_API_KEY = os.getenv("OPENAI_API_KEY")
NOTION_API_KEY = os.getenv("NOTION_API_KEY")
NOTION_DATABASE_ID = os.getenv("NOTION_DATABASE_ID")

openai_client = OpenAI(api_key=OPENAI_API_KEY)
notion = Client(auth=NOTION_API_KEY)

def analyze_transcript(transcript_text: str) -> MeetingAnalysis:
    """OpenAI Structured Outputs를 통해 회의록을 분석합니다."""
    system_prompt = (
        "당신은 고도로 훈련된 테크 기업의 스크럼 마스터이자 기술 서기입니다. "
        "제공된 회의 녹취록을 분석하여 결정 사항과 액션 아이템을 절대 누락 없이 구조화하세요."
    )
    
    completion = openai_client.beta.chat.completions.parse(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": system_prompt},
            {"role": "user", "content": transcript_text}
        ],
        response_format=MeetingAnalysis,
        temperature=0.2,
    )
    return completion.choices[0].message.parsed

def create_notion_meeting_page(analysis: MeetingAnalysis, db_id: str):
    """분석 결과를 노션 데이터베이스에 페이지 및 블록으로 생성합니다."""
    today_iso = datetime.now().strftime("%Y-%m-%d")
    
    # 1. 본문 블록 조립 (요약, 결정사항, To-Do)
    children_blocks = [
        {
            "object": "block",
            "type": "heading_2",
            "heading_2": {"rich_text": [{"text": {"content": "📌 회의 핵심 요약"}}]}
        }
    ]
    
    for point in analysis.summary_points:
        children_blocks.append({
            "object": "block",
            "type": "bulleted_list_item",
            "bulleted_list_item": {"rich_text": [{"text": {"content": point}}]}
        })
        
    children_blocks.append({
        "object": "block",
        "type": "heading_2",
        "heading_2": {"rich_text": [{"text": {"content": "🤝 주요 결정 사항"}}]}
    })
    
    for decision in analysis.key_decisions:
        children_blocks.append({
            "object": "block",
            "type": "bulleted_list_item",
            "bulleted_list_item": {"rich_text": [{"text": {"content": decision}}]}
        })

    children_blocks.append({
        "object": "block",
        "type": "heading_2",
        "heading_2": {"rich_text": [{"text": {"content": "✅ 액션 아이템 (To-Do)"}}]}
    })
    
    # To-Do 체크박스 블록 매핑
    for item in analysis.action_items:
        todo_text = f"[{item.priority}] {item.task} (담당: {item.assignee})"
        children_blocks.append({
            "object": "block",
            "type": "to_do",
            "to_do": {
                "rich_text": [{"text": {"content": todo_text}}],
                "checked": False
            }
        })

    # 2. 노션 페이지 생성 요청
    response = notion.pages.create(
        parent={"database_id": db_id},
        properties={
            "회의명": {
                "title": [{"text": {"content": analysis.title}}]
            },
            "일자": {
                "date": {"start": today_iso}
            },
            "카테고리": {
                "multi_select": [{"name": tag} for tag in analysis.tags]
            }
        },
        children=children_blocks
    )
    return response

if __name__ == "__main__":
    sample_meeting = """
    철수: 백엔드 API 배포가 금요일 저녁에 잡혀있는데, 결제 모듈 리팩토링 검증이 조금 덜 끝났습니다.
    영희: 그러면 배포 일정을 다음 주 화요일 오전 10시로 미루죠. 제가 QA 일정 다시 잡겠습니다.
    민수: 프론트엔드 쪽 에러 로깅 센트리(Sentry) 연동 작업은 내일까지 완료해서 PR 올리겠습니다.
    철수: 알겠습니다. 제가 내일 오후 3시까지 DB 마이그레이션 스크립트 작성해서 공유드릴게요.
    영희: 다들 동의하셨으니, 배포 일정 연기 공지는 제가 슬랙 #general 채널에 올리겠습니다.
    """
    print("1. 회의 분석 진행 중 (OpenAI)... ")
    analyzed_data = analyze_transcript(sample_meeting)
    
    print("2. 노션 페이지 생성 중... ")
    page = create_notion_meeting_page(analyzed_data, NOTION_DATABASE_ID)
    print(f"성공적으로 생성되었습니다! 노션 URL: {page['url']}")
```

## 5. 도구별 구현 방식 비교 분석

회의록 자동화를 구현할 수 있는 세 가지 대표 접근 방식을 실무 관점에서 비교해 봅니다.

| 비교 항목 | Python 스크립트 + Cron / Serverless | Make (구 Integromat) 노코드 | Notion AI 내장 도구 |
| :--- | :--- | :--- | :--- |
| **구현 난이도** | 중급 (API 키 관리 및 코드 배포 필요) | 초급 (GUI 블록 드래그 앤 드롭) | 최하 (클릭 몇 번으로 즉시 사용) |
| **커스텀 유연성** | **매우 높음** (Pydantic 스키마 완벽 제어, 데이터 전처리 자유) | 보통 (JSON 모듈 결합 필요, 분기 복잡성 증가) | 낮음 (정해진 프롬프트 템플릿에 종속) |
| **비용 구조** | **최저** (`gpt-4o-mini` 기준 회의당 약 5~10원) | 보통 (무료 티어 1,000 ops 초과 시 월 $9+) | 높음 (워크스페이스 인당 월 $8~10 정액제) |
| **보안 및 통제권** | 로컬 환경 또는 자체 VPC 내 프라이빗 실행 가능 | 서드파티 클라우드를 경유함 | 노션 클라우드 내부에서만 처리 |
| **추천 대상** | 개발팀, 맞춤형 인프라 구축 선호 조직 | 코딩 없이 빠르게 자동화를 도입하려는 기획/마케팅팀 | 단일 개인 사용자 및 간단한 일회성 정리 필요자 |

## 6. 실무 트러블슈팅 및 토큰 비용 최적화 노하우

### 1) STT 불용어 제거 및 컨텍스트 압축
음성 인식 모델(Whisper, Clova Speech 등)로 추출된 텍스트 원본은 "음...", "어...", "그게 말이죠"와 같은 감탄사와 침묵, 잡담이 전체 분량의 30% 이상을 차지합니다. 이를 그대로 OpenAI 모델에 전송하면 토큰 낭비가 심해집니다.
- 정규표현식(`re.sub`)을 활용해 반복되는 추임새를 1차 필터링하세요.
- 발화자 이름 뒤 콜론 포맷(`철수:`, `영희:`)을 표준화하여 모델이 대화 흐름을 더 적은 컨텍스트로 이해할 수 있도록 사전 가공합니다.

### 2) 노션 API의 블록 2,000자 제한 극복
노션 API는 단일 `rich_text` 객체의 글자 수를 최대 2,000자로 제한합니다. 긴 회의록의 경우 요약문이 2,000자를 초과하면 `400 validation_error`가 발생합니다. 아래 헬퍼 함수를 적용하여 텍스트를 2,000자 단위로 자동 청킹(Chunking)해 안전하게 전송하세요.

```python
def chunk_text(text: str, limit: int = 1900) -> list[str]:
    return [text[i:i+limit] for i in range(0, len(text), limit)]
```

### 3) 지수 백오프(Exponential Backoff) 재시도 로직 구성
네트워크 지연이나 OpenAI/Notion의 순간적인 레이트 리밋(HTTP 429)에 대응하기 위해 `tenacity` 라이브러리를 결합하면 무중단 자동화 파이프라인의 견고함을 극대화할 수 있습니다.
