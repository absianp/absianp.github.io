다운로드 폴더를 자동 정리할 때는 **같은 이름을 발견하면 내용을 비교하고, 내용이 다르면 새 이름을 붙이며, 중복 파일도 자동 삭제하지 않는 정책**부터 정해야 합니다. 이동 전에 목적지 존재 여부를 확인하는 것만으로는 충분하지 않습니다. 확인 직후 다른 프로그램이 같은 이름의 파일을 만들 수도 있기 때문입니다.

아래 예제는 기본 실행을 미리보기로 제한하고, `--apply`를 붙였을 때만 파일을 옮깁니다. 실제 이동에는 기존 목적지를 덮어쓰지 않는 하드 링크 생성과 원본 경로 삭제를 사용합니다. 이 방식은 **같은 파일시스템 안에서 하드 링크가 지원되는 환경**을 전제로 합니다.

## 실행 환경과 정리 범위를 먼저 제한하기

작성 기준일은 2026년 9월 17일이며, 예제 문법 기준은 Python 3.11입니다. 외부 패키지는 사용하지 않습니다. 이 초안의 코드는 실행 검증 전이므로, 실제 다운로드 폴더에 적용하기 전에 복사본에서 확인해야 합니다.

| 항목 | 예제의 기준 |
| --- | --- |
| 입력 | 사용자가 명시한 테스트 폴더 경로 |
| 탐색 범위 | 입력 폴더 바로 아래의 일반 파일 |
| 분류 기준 | `Path.suffix.lower()`로 얻은 마지막 확장자 |
| 제외 대상 | 하위 폴더, 심볼릭 링크, 규칙에 없는 확장자 |
| 기본 동작 | 이동 예정 목록 출력 |
| 실제 반영 | `--apply` 지정 시 실행 |
| 중복 정책 | 충돌한 목적지와 내용이 같으면 원본을 남기고 건너뛰기 |
| 이름 충돌 정책 | 내용이 다르면 `report (1).pdf`처럼 번호 붙이기 |

예를 들어 `PHOTO.JPG`는 이미지 폴더로 분류합니다. `archive.tar.gz`의 마지막 확장자는 `.gz`이므로, 복합 확장자를 별도로 다루려면 분류 규칙도 바꿔야 합니다.

브라우저 다운로드, 동기화, 파일 편집을 중지한 뒤 실행하세요. `.crdownload`나 `.part`를 제외하더라도, 다른 프로그램이 정상 확장자의 파일에 계속 쓰는 상황까지 감지할 수는 없습니다. 대상 폴더는 다른 사용자가 동시에 경로를 바꾸지 않는 개인 작업 폴더로 제한합니다.

[🔍 수치/출처 확인: 2026년 최신 기준 확인] 배포 환경의 Python 지원 버전과 파일시스템의 하드 링크 지원 여부를 확인하세요. 공식 확인 경로는 [pathlib 문서](https://docs.python.org/3/library/pathlib.html)와 [os.link 문서](https://docs.python.org/3/library/os.html#os.link)입니다.

## 이름 중복과 내용 중복은 별개의 조건이다

`report.pdf`라는 이름이 같다고 같은 문서는 아닙니다. 반대로 이름이 달라도 내용은 같을 수 있습니다. 이 예제는 전체 폴더의 중복을 제거하는 도구가 아니라, **분류 과정에서 목적지 이름이 충돌할 때 처리 방법을 결정하는 도구**입니다.

| 상황 | 처리 |
| --- | --- |
| 목적지에 같은 이름이 없음 | 해당 이름으로 이동 |
| 같은 이름이 있고 내용도 같음 | 이동하지 않고 원본 유지 |
| 같은 이름이 있지만 내용이 다름 | 번호가 붙은 이름을 순서대로 확인 |
| 같은 이름의 디렉터리나 심볼릭 링크가 있음 | 사용 중인 이름으로 보고 다음 번호 확인 |
| 이름이 다르지만 내용이 같음 | 별도 파일로 보관 |

내용 비교는 파일 크기를 먼저 확인한 뒤, 크기가 같으면 1 MiB씩 읽어 바이트를 비교합니다. 파일 전체를 한 번에 메모리에 올리지 않으며, 해시가 같다는 이유만으로 같은 내용이라고 판단하지도 않습니다. 다만 비교 도중 파일이 변경되지 않는다는 전제는 필요합니다.

번호 후보를 확인하다가 내용이 같은 파일을 만나면 건너뜁니다. 비어 있는 이름을 먼저 찾으면 그 이름을 사용하므로, 뒤쪽 번호까지 모두 검색하는 전역 중복 검사는 아닙니다.

[💡 사용자 경험/관점 추가: 동일한 이름으로 반복 다운로드하는 파일의 실제 사례와, 중복 원본을 남겨 두는 정책이 적합한 이유를 1~2문장으로 추가]

## 미리보기와 실제 이동을 한 스크립트로 구현하기

다음 내용을 `organize_downloads.py`로 저장합니다. 스크립트 자체는 정리 대상 폴더 밖에 두세요.

```python
import argparse
import json
import os
from datetime import datetime, timezone
from pathlib import Path

RULES = {
    '.pdf': 'documents',
    '.docx': 'documents',
    '.txt': 'documents',
    '.jpg': 'images',
    '.jpeg': 'images',
    '.png': 'images',
    '.zip': 'archives',
}
CHUNK = 1024 * 1024


def same_content(a, b):
    if b.is_symlink() or not b.is_file():
        return False
    if a.stat().st_size != b.stat().st_size:
        return False
    with a.open('rb') as left, b.open('rb') as right:
        while True:
            x = left.read(CHUNK)
            y = right.read(CHUNK)
            if x != y:
                return False
            if not x:
                return True


def choose_destination(src, folder):
    number = 0
    while True:
        name = src.name if number == 0 else (
            f'{src.stem} ({number}){src.suffix}'
        )
        dst = folder / name
        # 끊어진 심볼릭 링크도 사용 중인 이름으로 취급한다.
        if not os.path.lexists(dst):
            return 'move', dst
        if same_content(src, dst):
            return 'duplicate', dst
        number += 1


def record(log, event, src, dst=None, detail=None):
    row = {
        'time': datetime.now(timezone.utc).isoformat(),
        'event': event,
        'src': str(src),
        'dst': str(dst) if dst else None,
        'detail': detail,
    }
    try:
        log.write(json.dumps(row, ensure_ascii=False) + '\n')
        log.flush()
        os.fsync(log.fileno())
    except OSError as exc:
        # 기록에 실패하면 다음 파일을 처리하지 않는다.
        raise RuntimeError('기록 실패: 작업을 중단하고 경로를 확인하세요.') from exc


def run(root, apply, log=None):
    sources = sorted(root.iterdir(), key=lambda p: p.name)
    for src in sources:
        dst = None
        try:
            if src.is_symlink() or not src.is_file():
                continue
            group = RULES.get(src.suffix.lower())
            if group is None:
                continue
            folder = root / group
            if folder.is_symlink():
                raise OSError(f'분류 폴더가 심볼릭 링크입니다: {folder}')
            if folder.exists() and not folder.is_dir():
                raise NotADirectoryError(str(folder))

            if apply:
                folder.mkdir(exist_ok=True)

            while True:
                action, dst = choose_destination(src, folder)
                print(f'{action.upper()}: {src.name} -> {dst.relative_to(root)}')
                if not apply:
                    break
                if action == 'duplicate':
                    record(log, 'duplicate_kept', src, dst)
                    break

                record(log, 'intent', src, dst)
                try:
                    # 既存の目的地には上書きせず、競合時は再選択する。
                    os.link(src, dst)
                except FileExistsError:
                    continue

                record(log, 'linked', src, dst)
                src.unlink()
                record(log, 'moved', src, dst)
                break

        except OSError as exc:
            print(f'ERROR: {src.name}: {type(exc).__name__}: {exc}')
            if apply:
                record(log, 'error', src, dst, str(exc))


def main():
    parser = argparse.ArgumentParser()
    parser.add_argument('root', type=Path)
    parser.add_argument('--apply', action='store_true')
    args = parser.parse_args()
    root = args.root.expanduser().resolve(strict=True)
    if not root.is_dir():
        parser.error('root는 디렉터리여야 합니다.')

    if args.apply:
        # 기존 기록을 덮어쓰지 않도록 실행마다 새 파일을 만든다.
        stamp = datetime.now(timezone.utc).strftime('%Y%m%dT%H%M%S%fZ')
        log_path = root / f'.organize-{stamp}.jsonl'
        with log_path.open('x', encoding='utf-8') as log:
            print(f'LOG: {log_path}')
            run(root, True, log)
    else:
        run(root, False)


if __name__ == '__main__':
    main()
```

`os.link()` 바로 위의 주석은 “기존 목적지를 덮어쓰지 않고, 충돌하면 이름을 다시 선택한다”는 뜻입니다. 목적지 확인과 실제 생성 사이에 다른 파일이 생겨도 `FileExistsError`를 처리해 후보를 다시 고릅니다.

### 왜 일반적인 이동 함수 대신 하드 링크를 사용하는가?

`shutil.move()`나 이름 변경 함수는 목적지와 운영체제 조건에 따라 덮어쓰기 동작을 검토해야 합니다. 따라서 단순히 `if not dst.exists()`를 앞에 붙였다는 이유로 덮어쓰기 방지가 완성되지는 않습니다.

이 예제는 먼저 목적지 이름을 새 하드 링크로 생성합니다. 성공하면 원본과 목적지는 같은 파일 내용을 가리킵니다. 이후 원본 이름을 삭제하면 목적지 이름만 남습니다. 기존 목적지 이름이 있다면 링크 생성이 실패하므로 그 파일을 덮어쓰지 않습니다.

두 동작 전체가 하나의 원자적 이동인 것은 아닙니다. 중간에 프로그램이 종료되면 두 경로가 남을 수 있고, 그때는 한쪽을 편집하면 다른 쪽에서도 변경된 내용이 보입니다. 또한 서로 다른 파일시스템 사이에서는 사용할 수 없습니다. 지원하지 않는 환경에서는 오류를 기록하고 원본을 유지하며, 자동으로 다른 이동 방식으로 전환하지 않습니다.

## 복사본에서 미리보기와 결과를 확인하기

테스트 폴더를 다음처럼 준비합니다. 두 `report.pdf`에는 서로 다른 내용을 넣으세요.

```text
Downloads-test/
├── report.pdf
├── photo.JPG
└── documents/
    └── report.pdf
```

먼저 Python 버전과 예정 목록을 확인합니다. Windows에서 `python` 명령을 사용할 수 없다면 설치 환경에 맞게 `py -3`으로 바꾸세요.

```bash
python --version
python organize_downloads.py "/path/to/Downloads-test"
```

예상 출력은 다음과 같습니다. 미리보기에서는 분류 폴더와 로그 파일을 만들지 않습니다.

```text
MOVE: photo.JPG -> images/photo.JPG
MOVE: report.pdf -> documents/report (1).pdf
```

결과를 확인한 뒤 같은 테스트 폴더에 적용합니다.

```bash
python organize_downloads.py "/path/to/Downloads-test" --apply
```

정상 완료되면 `photo.JPG`는 `images`로 이동하고, 기존 `documents/report.pdf`는 그대로 남습니다. 입력 파일은 `documents/report (1).pdf`로 이동합니다. 미리보기 이후 폴더 상태가 달라졌다면 실제 적용 시 이름을 다시 계산하므로 결과가 달라질 수 있습니다.

내용 중복도 따로 시험하세요. `documents/report.pdf`의 복사본을 입력 폴더에 같은 이름으로 놓고 실행하면 `DUPLICATE`가 출력되고 두 경로 모두 유지되어야 합니다. 중복 원본을 보존하는 정책이므로 재실행해도 같은 항목이 다시 표시됩니다.

## 이동 기록은 성공 여부와 중간 상태를 구분해 읽기

실제 적용 시 입력 폴더에 실행별 `.organize-날짜.jsonl` 파일을 만듭니다. 각 줄이 독립적인 JSON 레코드입니다.

| 이벤트 | 의미와 확인할 사항 |
| --- | --- |
| `intent` | 해당 목적지로 작업을 시도하려고 기록함 |
| `linked` | 목적지 링크 생성에 성공함. 원본 이름은 아직 남아 있을 수 있음 |
| `moved` | 원본 이름 삭제까지 완료함 |
| `duplicate_kept` | 내용이 같은 충돌 파일을 발견해 원본을 유지함 |
| `error` | 해당 파일 처리 중 운영체제 오류가 발생함 |

로그는 파일 이동과 하나의 트랜잭션으로 묶이지 않습니다. `moved`가 없다는 이유만으로 이동하지 않았다고 단정하면 안 됩니다. 원본 삭제 직후 기록에 실패했을 수도 있습니다. 반대로 `linked`만 남아 있다면 두 경로가 모두 존재할 수 있습니다.

복구할 때는 기록의 `src`와 `dst`가 실제로 존재하는지부터 확인합니다. 두 경로가 같은 파일인지 확인하려면 Python의 `Path.samefile()`을 사용할 수 있습니다. 로그만 보고 일괄 삭제하거나 되돌리지 마세요. 기록에는 절대 경로가 포함되므로 외부 공유 전 사용자 이름과 폴더명을 가립니다.

## 권한 오류와 사용 중인 파일에 대응하기

| 증상 | 가능한 원인 | 다음 조치 |
| --- | --- | --- |
| `PermissionError` | 읽기·쓰기·삭제 권한 부족 또는 파일 잠금 | 관련 앱을 닫고 사용자 계정의 폴더 권한 확인 |
| 다른 파일시스템 관련 오류 | 분류 폴더가 별도 마운트나 볼륨에 위치 | 같은 파일시스템의 테스트 폴더에서 재확인 |
| 하드 링크 지원 관련 오류 | 파일시스템 또는 저장소 정책의 제한 | 지원 환경으로 범위를 좁히거나 별도 복사·검증 절차 설계 |
| `NotADirectoryError` | `images` 같은 분류 폴더 이름을 파일이 차지함 | 해당 파일을 확인한 뒤 이름 변경 |
| `FileNotFoundError` | 실행 중 다른 프로그램이 파일을 이동·삭제함 | 다운로드·동기화를 멈추고 미리보기 재실행 |
| 기록 실패로 작업 중단 | 저장 공간 부족 또는 로그 쓰기 실패 | 공간과 권한을 확인하고 마지막 `src`·`dst` 상태 점검 |

사용 중인 파일이 항상 오류를 내는 것은 아닙니다. 운영체제와 앱의 파일 열기 방식에 따라 링크 생성이나 원본 이름 삭제가 성공할 수도 있습니다. 따라서 예외 처리는 다운로드 완료나 파일 안정성을 보증하지 않습니다.

목적지 생성 후 원본 삭제가 실패했다면 두 경로가 남습니다. 코드는 목적지를 자동 삭제하지 않습니다. 로그와 실제 경로를 확인한 뒤 정리해야 합니다.

[💡 사용자 경험/관점 추가: 사용하는 운영체제와 동기화 프로그램에서 겪은 잠금 또는 권한 오류, 해결에 도움이 된 조치를 1~2문장으로 추가]

## 자동 실행에 등록하기 전 확인할 항목

- 다른 내용의 동명 파일을 넣고 기존 목적지가 바뀌지 않는지 확인합니다.
- 같은 내용의 동명 파일을 넣고 원본이 보존되는지 확인합니다.
- 실제 적용 후 로그의 `moved`와 목적지 파일을 대조합니다.
- 분류 규칙에 없는 파일과 하위 폴더가 유지되는지 확인합니다.
- 백업을 확보하고 다운로드·편집·동기화가 멈춘 시간에만 실행하도록 정합니다.

운영체제, 파일시스템, 권한 설정이 바뀌면 이동 가능 여부도 달라집니다. 실제 다운로드 폴더를 지정하기 전에 복사본에서 `python organize_downloads.py "/path/to/Downloads-test"`를 실행하고, 출력된 목적지부터 확인하세요.
